ミニゲームを1つに集めるための Unity Package 入門（全7回）

【1-01】ミニゲームを1つに集めよう【1章：パッケージ編】

  1. クリア条件：今回何を作るのか、そのために何を提出するのかが分かればOK！

  2. ここからは別巻、Unity Packageの使い方です。
    今回のゲームジャムでは、各チームが作ったミニゲームを1つのゲームにまとめます。タイトル画面から好きなミニゲームを選んで遊べる、いわゆるミニゲーム集です。

  3. でも、ここで問題があります。ミニゲームはチームごとに別々のUnityプロジェクトで作られています。

    Aチームのプロジェクト   ← 迷路ゲーム
Bチームのプロジェクト   ← シューティング
Cチームのプロジェクト   ← リズムゲーム

    これを最終的に、1つのプロジェクトの中に全部入れる必要があります。

    統合プロジェクト
 ├ 迷路ゲーム
 ├ シューティング
 └ リズムゲーム

  4. 「プロジェクトのフォルダごと渡せばいいのでは？」と思うかもしれませんが、それだとプロジェクトが3つ並ぶだけで、1つのゲームにはなりません。
    必要なのは「プロジェクトそのもの」ではなく、「そのミニゲームを動かすのに必要なファイル一式」を取り出して渡すことです。

  5. そのための仕組みが、Unityに用意されている Unity Package です。

    用語：Unity Package（.unitypackage）Unityのプロジェクトから、指定したファイルをまとめて1つのファイルに書き出したもの。受け取った側は、それを自分のプロジェクトに読み込むと、フォルダ構成そのままでファイルが追加されます。

  6. 今回のゲームジャムでの流れは、こうなります。

    ① 各チーム：自分のミニゲームを .unitypackage に書き出す
                ↓
② 各チーム：できたファイルを提出する（Discordなど）
                ↓
③ 統合担当：全部を統合プロジェクトに読み込む
                ↓
④ 統合担当：タイトル画面から各ミニゲームへつなぐ

    この別巻では、①の書き出し（1-02〜1-05）と、③の読み込み（1-06）を扱います。

  7. 【最重要】提出するファイルの名前は、全チーム統一します。

    GameJam_2026_07_Team<チーム名>_<ゲームタイトル>

    例：

    GameJam_2026_07_TeamAlpha_MazeRunner.unitypackage
GameJam_2026_07_TeamBravo_ShootingStar.unitypackage
GameJam_2026_07_TeamCharlie_RhythmCat.unitypackage

    ※<> は書きません。Team の後にそのままチーム名をつなげます。
    ※半角英数とアンダースコア（_）だけを使ってください。日本語やスペースが入ると、読み込む側で不具合の原因になります。

  8. なぜ名前を統一するのか。統合担当の画面には、全チームのファイルが並びます。

    ⭕ 統一されている場合
  GameJam_2026_07_TeamAlpha_MazeRunner.unitypackage
  GameJam_2026_07_TeamBravo_ShootingStar.unitypackage
  GameJam_2026_07_TeamCharlie_RhythmCat.unitypackage
  → どれが誰のもので、いつの提出物か一目で分かる

✕ バラバラの場合
  game.unitypackage
  最新版.unitypackage
  test2.unitypackage
  → 中身を開くまで分からない。同名ファイルで上書き事故も起きる

  9. 今回の目的（ミニゲームを1つに集める）と、提出するもの（決まった名前の.unitypackage）が分かったら、今回は完成です！
    次回は、書き出す前の準備をします。

【1-02】書き出す前にフォルダをまとめよう【1章：パッケージ編】

  1. クリア条件：自分のミニゲームのファイルが、1つのフォルダにまとまっていればOK！

  2. 書き出しの前に、準備が必要です。ここをやらないと、統合するときに全チームのファイルが混ざります。

  3. まず、よくない例から見てみましょう。作りながら進めると、だいたいAssetsフォルダはこうなっています。

    Assets/
 ├ Scenes/
 ├ Scripts/
 ├ Images/
 ├ Prefabs/
 └ Audio/

    一見きれいですが、このまま書き出すと問題が起きます。
    統合プロジェクトに3チーム分を読み込むと、こうなるからです。

    Assets/
 ├ Scenes/     ← A・B・C チームのシーンが全部ここに入る
 ├ Scripts/    ← 3チーム分のスクリプトが混ざる
 ├ Images/     ← 3チーム分の画像が混ざる
 └ ...

    どれが誰のファイルか分からなくなりますし、同じ名前のファイルがあると上書きされます。
    Player.cs や Title.unity のような名前は、まず間違いなくかぶります。

  4. そこで、書き出す前に自分のミニゲーム専用のフォルダを1つ作って、その中に全部入れます。

    Assets/
 └ GameJam_2026_07_TeamAlpha_MazeRunner/
     ├ Scenes/
     ├ Scripts/
     ├ Images/
     ├ Prefabs/
     └ Audio/

    こうしておけば、統合プロジェクトに読み込んでも、チームごとにきれいに分かれます。

    Assets/
 ├ GameJam_2026_07_TeamAlpha_MazeRunner/
 ├ GameJam_2026_07_TeamBravo_ShootingStar/
 └ GameJam_2026_07_TeamCharlie_RhythmCat/

  5. フォルダ名は、提出ファイルと同じ名前にしてください。

    GameJam_2026_07_Team<チーム名>_<ゲームタイトル>

    ファイル名とフォルダ名がそろっていると、統合担当が「このフォルダはどのチームのものか」を確認せずに済みます。

  6. では作りましょう。UnityのProjectウィンドウで、Assetsフォルダを右クリック →「Create」→「Folder」。
    名前を GameJam_2026_07_Team○○_○○○ にします。

  7. 次に、既存のフォルダをこの中へ移動します。

    Projectウィンドウでフォルダをまとめた状態

    必ずUnityのProjectウィンドウ上でドラッグして移動してください。
    エクスプローラー（Finder）で直接動かすと、Unityが参照を追えなくなって、シーンからスクリプトや画像が外れることがあります。

    用語：.metaファイルUnityが自動で作る、素材とセットの設定ファイル。Unity上で移動すれば.metaも一緒に動くので参照は壊れませんが、エクスプローラーで動かすと.metaだけ取り残されて壊れる場合があります。フォルダの整理はUnity上で、が鉄則です。

  8. 移動が終わったら、Unityを再生（Play）して、ゲームがちゃんと動くか確認しましょう。
    ここで動かなくなっていたら、参照が外れている可能性があります。書き出す前に必ず直してください。

  9. 【この時点でよくあるトラブル】

    症状原因と対処
    シーンを開いたらオブジェクトが白い四角になった画像の参照が外れている。Inspectorで画像を割り当て直す
    Missing (Mono Script) と表示されるスクリプトの参照が外れている。Inspectorでスクリプトを割り当て直す
    Consoleに赤いエラーが出るエラー内容を読んで対処。まず移動前の状態に戻せないか確認

  10. Assetsの中に自分のミニゲーム用フォルダが1つでき、その中に全ファイルが入って、ゲームが動いたら今回は完成です！
    次回は、そのフォルダの外に忘れ物がないかを確認します。

【1-03】フォルダの外の忘れ物を確認しよう【1章：パッケージ編】

  1. クリア条件：自分のフォルダの外にある「持っていけないもの」に気づけばOK！

  2. 前回、ミニゲームのファイルを1つのフォルダにまとめました。
    ただし、Unity Packageに入らないものがいくつかあります。ここを知らずに提出すると、統合したときに「自分の環境では動いたのに、統合したら動かない」が起きます。

  3. Unity Packageに入るもの／入らないものは、こう分かれます。

    種類場所パッケージに入る？
    画像・音・スクリプト・シーン・プレハブAssets の中⭕ 入る（選んだものだけ）
    Package Manager で入れた機能Packages✕ 入らない
    タグ・レイヤー・入力設定・物理設定などProject Settings✕ 入らない
    Build Settings のシーン一覧Project Settings✕ 入らない

  4. 【確認1】自分のフォルダの外にあるファイルを使っていないか

    前回作ったフォルダの外に、使っている素材が残っていないか確認しましょう。
    例えば「共通で使うフォントを Assets/Fonts に置いたまま」だと、フォルダごと書き出しても付いてきません。

    確認方法は簡単です。自分のミニゲームのシーンを開いて、Hierarchyのオブジェクトを1つずつ選び、Inspectorに表示されている素材を確認する……のは大変なので、書き出しのときにUnityが自動で調べてくれる機能を使います（次回1-04の「Include dependencies」）。

    ただし自動でも拾えないものがあるので、下の2つは自分で確認してください。

  5. 【確認2】Package Manager で追加した機能

    TextMeshPro、Cinemachine、DOTweenなど、後から追加した機能はパッケージに入りません。
    使っている場合は、提出のときに「この機能を使っています」と伝える必要があります。

    確認するには、Window > Package Management > Package Manager を開きます。

    Package Managerを開くメニュー

    左側の「In Project」を選ぶと、このプロジェクトで使っている機能の一覧が表示されます。

    Package ManagerのIn Project表示

    ※Unityに最初から入っているものはそのままでOKです。自分で追加した覚えのあるものだけメモしておいてください。

  6. 【確認3】タグ・レイヤー・入力設定

    Project Settings の中身は、パッケージには一切入りません。特に次の3つはミニゲームでよく使うので要注意です。

    • Tag（タグ）：Player や Enemy など、自分で追加したタグ
    • Layer（レイヤー）：自分で追加したレイヤー、Layer Collision Matrix の設定
    • Input（入力）：Input Managerで追加した軸の名前、Input Systemの設定ファイル

    Edit > Project Settings... を開いて、左のリストから「Tags and Layers」を選びます。「Tags」の欄を開いて、自分で追加したものがあればメモしておきましょう。

    Tags and Layersの画面

    ※スクショのように「List is empty」と表示されていれば、自分で追加したタグは無いということです。この場合は何も申告しなくて大丈夫。
    ※Untagged MainCamera Player などの最初からあるタグは、統合先にも最初からあるので大丈夫です。

  7. 【対策】スクリプトでタグを使っている場合の注意

    例えばスクリプトにこう書いてあるとします。

    if (other.gameObject.tag == "Item")

    このとき統合先に Item タグが無いと、実行時にエラーが出てゲームが止まります。
    自分で追加したタグは必ず申告してください。統合担当が統合先に同じタグを追加します。

  8. 【まとめ】提出時に一緒に伝える情報

    パッケージファイルと一緒に、この3つをDiscordなどで伝えましょう。

    ・追加した機能：TextMeshPro、Cinemachine
・追加したタグ：Item、Goal
・追加したレイヤー：Ground、Trap
・最初に開くシーン：Title_TeamAlpha.unity

    ※「最初に開くシーン」は、統合担当がタイトル画面からつなぐときに必要です。必ず書いてください。

  9. 自分のフォルダの外に何があるか把握できて、伝える内容がまとまったら、今回は完成です！
    次回はいよいよ書き出します。

【1-04】unitypackageに書き出そう【1章：パッケージ編】

  1. クリア条件：決められた名前で .unitypackage ファイルが作れればOK！

  2. 準備ができたので、書き出します。操作自体は3ステップで終わります。

  3. まず、Projectウィンドウで自分のミニゲーム用フォルダを右クリックします。
    メニューの中から「Export As Asset Package...」を選んでください。

    右クリックメニューのExport As Asset Package

    ※Unityのバージョンによっては「Export Package...」という名前です。どちらも同じ機能です。
    ※Assets を右クリックすると全部が対象になります。必ず自分のフォルダを選んでから右クリックしてください。

  4. 「Exporting package」というウィンドウが開きます。ここが書き出しの設定画面です。

    Exporting packageウィンドウ
    • 中央のリスト：書き出すファイルの一覧。チェックが付いているものが書き出されます
    • All / None：全部にチェックを付ける／全部外す
    • リストの各行のチェックボックス：個別に外すこともできます

  5. 下にある2つのチェックボックスは、両方チェックを入れたままにしてください。

    Include dependenciesとInclude all scripts
    • Include dependencies：選んだファイルが使っている他のファイルも自動で追加する
    • Include all scripts：プロジェクト内のスクリプトをまとめて追加する
    用語：Include dependencies（依存関係を含める）例えばプレハブを1つ選んだとき、そのプレハブが使っている画像やスクリプトも一緒に書き出す設定です。チェックを外すと、統合先で「絵が付いていない」「スクリプトが無い」状態になります。特別な理由がなければ、必ずチェックを入れてください。

  6. 準備ができたら、右下の「Export...」ボタンを押します。
    保存先を聞かれるので、分かりやすい場所（デスクトップなど）を選び、ファイル名を入力します。

  7. 【最重要】ファイル名は、決められた形式で付けてください。

    GameJam_2026_07_Team<チーム名>_<ゲームタイトル>
    保存ダイアログでのファイル名

    ※スクショの例では GameJam_2026_07_TeamKujata_MagicalShooting.unitypackage としています。
    ※.unitypackage の部分は自動で付くので、入力しなくて大丈夫です。
    ※半角英数とアンダースコア（_）だけを使ってください。

  8. 「保存」を押すと書き出しが始まります。プロジェクトの大きさによっては1分ほどかかります。
    指定した場所に .unitypackage ファイルができていれば成功です。

  9. ファイルサイズを確認しておきましょう。

    • 数MB〜数十MB：正常です
    • 数百バイト〜数KB：ほとんど中身が入っていません。手順3でフォルダを選び忘れた可能性があります
    • 1GB以上：Libraryフォルダなど、本来入らないものが混ざっている可能性があります。書き出す対象を見直してください

  10. 決められた名前の .unitypackage ファイルができたら、今回は完成です！
    ただし、このまま提出してはいけません。次回、ちゃんと動くかを自分で確認します。

【1-05】提出前に自分で動作確認しよう【1章：パッケージ編】

  1. クリア条件：空のプロジェクトに読み込んで、動くか確認できればOK！

  2. 書き出したパッケージ、そのまま提出したくなりますが、あと1ステップだけ待ってください。
    自分のプロジェクトでは動くのに、統合先では動かないというのが、パッケージで一番多いトラブルです。

  3. 理由は1-03で説明した通りです。パッケージには入らないものがあるからです。

    • Package Managerで追加した機能
    • タグ、レイヤー、入力設定

    自分のプロジェクトにはこれらが全部そろっているので、当然動きます。でも統合先は別のプロジェクトです。

  4. そこで、空のプロジェクトを作って、自分のパッケージだけを読み込んでみます。
    ここで動けば、統合先でもほぼ確実に動きます。動かなければ、統合前に自分で直せます。

  5. UnityHubで「New project」を押して、新しいプロジェクトを作りましょう。

    • テンプレート：自分のミニゲームと同じもの（2Dで作ったなら Universal 2D）
    • Unityバージョン：チームで決めたバージョン（今回は 6000.3.15f1）
    • プロジェクト名：ImportTest など、分かるもの

    ※バージョンが違うと、それだけで動かないことがあります。ここは必ずそろえてください。

  6. 新しいプロジェクトが開いたら、Assets > Import Package > Custom Package... を選び、書き出したパッケージを読み込みます。
    （詳しい手順は次回1-06で説明します。ここでは読み込んで動かすだけです）

  7. 読み込んだら、この4つを確認してください。

    確認項目見るところ
    エラーが出ていないかConsoleに赤いエラーが無いか
    シーンが開けるか自分のシーンをダブルクリックして開く
    見た目が崩れていないか白い四角（Missing）になっている絵が無いか
    実際に遊べるかPlayボタンを押して動かしてみる

  8. 【よくあるエラー1】赤いエラーで「型または名前空間が見つかりません」

    実際にやってみたところ、こういうエラーが出ました。

    読み込み後に出たエラー

    これは、スクリプトの先頭にある using が、統合先に無い機能を指しているときに出ます。

    using Unity.VisualScripting;   // ← この機能が統合先に無い
using Unity.Mathematics;       // ← これも

    対処は2つあります。

    • その機能を実際に使っていない場合：using の行を消す（多くの場合こちらです。エディタが自動で追加しただけ）
    • 実際に使っている場合：1-03で説明した通り、「この機能を使っています」と統合担当に申告する

  9. 【よくあるエラー2】絵が白い四角になる

    1-05でも触れた.metaの問題か、書き出しのときに「Include dependencies」のチェックが外れていた可能性があります。
    もう一度1-04の手順で、チェックを入れて書き出し直してください。

  10. 【よくあるエラー3】タグ関連のエラーで止まる

    Tag: ○○ is not defined のようなエラーが出たら、自分で追加したタグを使っています。
    統合先に同じタグを追加してもらう必要があるので、タグ名を必ず申告してください。

  11. 空のプロジェクトで問題なく動いたら、いよいよ提出です。
    決められた名前のファイルと一緒に、1-03でまとめた情報を書いて提出しましょう。

    【提出】GameJam_2026_07_TeamAlpha_MazeRunner.unitypackage

・最初に開くシーン：Title_TeamAlpha.unity
・追加した機能：TextMeshPro
・追加したタグ：Item、Goal
・追加したレイヤー：なし
・操作方法：矢印キーで移動、スペースでジャンプ

  12. 空のプロジェクトで動作確認ができて、提出できたら、今回は完成です！
    ここまでで、書き出す側の作業は終わりです。次回は受け取る側（統合担当）の作業を見ていきます。

【1-06】統合プロジェクトに読み込もう【1章：パッケージ編】

  1. クリア条件：受け取ったパッケージを統合プロジェクトに読み込めればOK！

  2. ここからは受け取る側、統合担当の作業です。
    ※自分が統合担当でない人も、目を通しておいてください。自分の提出物がどう扱われるかが分かると、提出物の作り方が変わります。

  3. 全チームのパッケージがそろったら、統合プロジェクトを開きます。
    まだ無ければ、UnityHubで新規プロジェクトを作ってください（テンプレートとバージョンは、チームで決めたものにそろえます）。

  4. Assets > Import Package > Custom Package... を選びます。

    Import Packageメニュー

  5. ファイル選択の画面が出るので、1チーム分のパッケージを選びます。
    ※必ず1つずつ読み込んでください。まとめて読み込むと、問題が起きたときにどのチームのものが原因か分からなくなります。

  6. 「Import Unity Package」というウィンドウが開きます。中身の一覧が表示されるので、そのまま右下の「Import」を押します。

    Import Unity Packageウィンドウ
    • 上部にパッケージ名が表示されます。ここで名前を確認しておくと、どのチームのものか分かります
    • 緑の「New」は新しく追加されるファイル、「Changed」は既にあるファイルが上書きされるという意味です

    ※「Changed」が出たら要注意です。他のチームのファイルを上書きしようとしている可能性があります。その場合はImportを押さず、提出者に確認してください。

  7. 読み込みが終わると、Projectウィンドウにファイルが追加されます。

    読み込み後のProjectウィンドウ

    1-02でフォルダをまとめてもらっているので、チームごとにきれいに分かれているはずです。

    チームごとに分かれた状態

  8. 【ここからが本番】読み込んだ直後に必ず確認すること

    Consoleを見てください。赤いエラーが出ていたら、そのチームのミニゲームはまだ動きません。

    読み込み後に出たエラー

    実際にやってみたところ、3つのエラーが出ました。内容はこれです。

    エラーの詳細
    error CS0234: The type or namespace name 'VisualScripting'
does not exist in the namespace 'Unity'

    これは「スクリプトが使っている機能が、このプロジェクトに入っていない」という意味です。1-03で説明した「パッケージに入らないもの」が原因です。

  9. 【対処】足りない機能を追加する

    Window > Package Management > Package Manager を開いて、エラーに出ている機能を追加します。
    または、その機能を実際には使っていない場合、スクリプトの using の行を消せば直ります（提出者に確認してから消しましょう）。

  10. 【注意】エラーがあるまま再起動すると、Safe Modeになる

    コンパイルエラーが残った状態でUnityを開き直すと、この画面が出ます。

    Enter Safe Mode?ダイアログ
    • Enter Safe Mode：エラーを直すことに集中できるモードで開く
    • Ignore：とりあえず無視して開く（エラーは残ったまま）

    どちらを選んでも、エラーを直さない限りゲームは動きません。エラーは読み込んだその日に直すのが鉄則です。

  11. 【全チーム分を読み込む手順】

    1チーム読み込む → エラーを確認 → 直す → 動作確認 → 次のチームを読み込む

    この順番を必ず守ってください。まとめて読み込むと、エラーが混ざって原因が分からなくなります。

  12. 【最後に】シーンをBuild Settingsに登録する

    各ミニゲームのシーンは、読み込んだだけではビルドに含まれません。
    File > Build Profiles を開いて、Scene Listに全ミニゲームのシーンを追加してください。
    ※1-05で各チームに申告してもらった「最初に開くシーン」が、ここで役に立ちます。

  13. 全チームのパッケージを読み込めて、エラーが無くなったら、今回は完成です！
    次回は最終回、提出前のチェックリストをまとめます。
