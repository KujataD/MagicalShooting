# 【1-01】Gitってなに？なんで必要？【1章：Git導入編】

1. クリア条件：Gitが何をしてくれるものか、ざっくり分かればOK！

2. ここからは別巻、チーム制作のためのGit編です。
   今回は手を動かしません。まず「なんでこれを覚えるの？」をハッキリさせておきましょう。ここが分かっていないと、この先の操作が意味不明な暗記になってしまうので。

3. まず、こんな経験ありませんか？

   ```
   キャラ絵_最終.psd
   キャラ絵_最終2.psd
   キャラ絵_最終_修正版.psd
   キャラ絵_ほんとの最終.psd
   キャラ絵_ほんとの最終_これで決定.psd
   ```

   あるあるですね。これは、ファイル名で変更履歴を管理している状態です。
   そして大体、3日後には「どれが最新？」「あの時の色に戻したいけど、どのファイルだっけ？」となります。

4. Gitを使うと、ファイルは「キャラ絵.psd」1つだけになります。
   そのかわり、キリのいいところで**その時点の状態を記録**していきます。この記録が積み重なって履歴になります。

   用語：Git（ギット）
   ファイルの変更履歴を記録・管理するソフト。ゲームのセーブに近く、**上書きではなく、記録するたびにセーブデータが1つずつ増えていきます**。だから、いつでも好きな時点の状態に戻せます。

5. でも、Gitが本当に効いてくるのはチーム制作のときです。
   たとえば、AさんがタイトルUIを作り、Bさんが敵の動きのスクリプトを書いているとします。Gitを使わずにUnityプロジェクトを共有すると、どうなるか。

   - Aさん「プロジェクトフォルダをzipで送るね」
   - Bさん「ありがとう。こっちも直したから送り返すね」
   - Aさん「その間にこっちも直しちゃった。どっちが正しいの？」
   - 二人「……」

   zipを送り合う運用は、必ずどこかで誰かの作業が消えます。

6. Gitを使うと、こうなります。

   - 全員が同じ場所（GitHub上のリポジトリ）のデータを見る
   - 各自が自分の作業をして、終わったらそこに送る
   - Gitが「AさんはUIのファイル、Bさんはスクリプトのファイルを変えたんだな」と判断して、**自動で1つにまとめてくれる**

   触っているファイルが違う限り、2人の作業は自動的に1つにまとまります。ここがGitの一番の強みです。

   用語：マージ
   別々に進めた作業を1つにまとめること。ほとんどの場合、Gitが自動でやってくれます。

7. まとめると、Gitがやってくれるのはこの3つです。

   - **変更履歴を全部残す**（いつでも過去の状態に戻せる）
   - **複数人の作業を1つにまとめる**（zipの送り合いが不要になる）
   - **誰がいつ何を変えたかを記録する**（作業ログが自動で残る）

8. 「絵や音を作るだけなら関係ないのでは？」と思うかもしれませんが、Unityではそうもいきません。
   画像を1枚追加するだけでもプロジェクトのファイルが増えますし、シーンの設定も書き換わります。絵もアニメも音もスクリプトも、全部まとめてGitの管理下に入ります。
   このサークルでは全員が同じプロジェクトを触るので、**全員が使えるようになっておく**必要があります。

9. 最後に、心構えをひとつ。
   Gitは最初、用語が多くて戸惑うと思います。コミット、プッシュ、ブランチ、マージ……たぶん何度か「わからん」となります。

   でも安心してください。実際に毎日使う操作は、この4つだけです。

   - **コミット**（変更を記録する）
   - **プッシュ**（記録をGitHubに送る）
   - **プル**（GitHubから最新を取ってくる）
   - **ブランチ**（作業する場所を分ける）

   残りは全部この応用です。操作はすべて、マウスで使えるアプリ（1-04で入れます）から行います。

10. Gitが「履歴が全部残る、みんなで使える保存場所」だとイメージできたら、今回は完成です！
    次回は、その保存場所を用意するところから始めます。
