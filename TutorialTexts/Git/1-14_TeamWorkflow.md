## 【A】毎日の作業フロー（これだけ覚えればOK）

```
① Discordで「今日は○○を触ります」と宣言
        ↓
② Fork：develop に切り替えて Pull（最新を取得）
        ↓
③ Fork：Branch で feature/○○ を作る
        ↓
④ Unity で作業する（こまめに保存）
        ↓
⑤ Unity を閉じる
        ↓
⑥ Fork：変更を Stage → コミットメッセージを書く → Commit
   （④〜⑥は何回繰り返してもOK。こまめに！）
        ↓
⑦ Fork：Push（GitHubに送る）
        ↓
⑧ GitHub：Pull Request を作る（base は develop ！）
        ↓
⑨ Discordで「PR出しました、確認お願いします」
        ↓
⑩ 確認OK → GitHub：Merge → ブランチ削除
        ↓
⑪ Discordで「マージしました」→ 全員が develop を Pull
        ↓
   ①に戻る
```

---

## 【B】ブランチの役割（3つだけ）

| ブランチ | 役割 | 触り方 |
|---|---|---|
| **main** | 完成版。いつでも遊べる状態 | 直接触らない。提出・公開のときだけ |
| **develop** | 開発版。全員の作業の集合場所 | 直接コミットしない。PR経由で入れる |
| **feature/○○** | 個人の作業場所 | **ここで作業する**。1作業1本 |

ブランチ名の例：`feature/enemy-graphics` `feature/title-ui` `feature/bgm-stage1`

---

## 【C】Unityチーム制作の決めごと（5ヶ条）

1. **同じシーン・同じプレハブを2人で同時に触らない**
   → いちばん事故る。作業前にDiscordで宣言する

2. **.metaファイルも必ず一緒にコミットする**
   → 忘れると相手の環境で絵やスクリプトの紐付けが外れる

3. **Pull / ブランチ切り替えのときは Unity を閉じる**
   → 開いたままやるとUnityの表示やデータがおかしくなる

4. **Libraryフォルダは共有しない**
   → .gitignoreで除外済み。各自のPCで自動生成される

5. **作業前は必ず develop を Pull する**
   → 古い状態から作業を始めると、あとでまとめられなくなる

## 【D】チームでの分担の決め方

作業がぶつからないように、**ファイル単位で担当を決める**のがコツです。

| 良い分担 ⭕ | 避けたい分担 ✕ |
|---|---|
| Aさん：Enemyプレハブ周り<br>Bさん：Playerプレハブ周り | Aさん：敵の動き<br>Bさん：敵の見た目<br>→ 同じファイルを触ることになる |
| Aさん：TitleScene<br>Bさん：GameScene | 2人で同じGameSceneを編集 |
| 素材の差し替えはAさんが一括で行う | 全員が好きなタイミングで素材を追加 |

**大きなシーンは、機能ごとにプレハブに分けておく**と分担しやすくなります。
（例：UI一式をプレハブ化 → UI担当はプレハブだけ触ればよく、シーン本体は触らない）

## 【E】困ったとき逆引き表

| こうなった | こうする |
|---|---|
| **mainで作業してしまった**（まだコミット前） | Forkでブランチを作って切り替える。変更はそのまま新しいブランチに引き継がれる |
| **mainにコミットしてしまった**（まだPush前） | まずFork右上の Branch で新しいブランチを作成 → そのあとmainを1つ前に戻す（該当コミットを右クリック →「Reset ... to Here」）。不安なら代表の人に相談 |
| **Pushが拒否された**（Push rejected） | 先にPullする → 自動でまとめられればもう一度Push |
| **コンフリクトした** | 1-13参照。シーンファイルなら、片方を丸ごと採用してもう片方はUnityでやり直すのが速い |
| **相手の環境だけ絵が消える** | .metaファイルのコミット漏れ。Assetsの.metaを全部コミットし直す |
| **プロジェクトが壊れた気がする** | フォルダをリネームして、GitHubからクローンし直す。Push済みのものは消えない |
| **間違えてPRをマージした** | GitHubのPR画面に「Revert」ボタンがある。取り消し用のPRが自動で作られる |
| **どのブランチにいるか分からない** | Forkの左メニューでチェックマークが付いているのが現在地 |
| **Unityが「シーンが壊れています」と言う** | Unityを閉じて、Forkで該当ファイルを「Discard changes」→ Pullし直す |
