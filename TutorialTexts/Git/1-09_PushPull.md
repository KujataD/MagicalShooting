# 【1-09】プッシュ＆プルしよう【1章：Git導入編】

1. クリア条件：自分のコミットをGitHubに送って、メンバーの変更を受け取れればOK！

2. 前回のコミットは、**自分のPCの中だけ**の記録でした。
   Gitでは「自分のPCの記録」と「GitHub上の記録」が別々に存在していて、この2つは自動では同期しません。自分のタイミングで送ったり受け取ったりします。

3. 今回覚える操作は2つ。送るか、受け取るかだけです。

   | 操作 | 向き | 何をする |
   |---|---|---|
   | **プッシュ（push）** | 自分のPC → GitHub | 自分のコミットをGitHubに送る |
   | **プル（pull）** | GitHub → 自分のPC | メンバーのコミットを自分のPCに取り込む |

   用語：プッシュ / プル
   push は「押し出す」、pull は「引っぱる」。自分から見て、送り出すのか、引き寄せるのかで覚えると迷いません。

4. まずプッシュしてみましょう。Forkの上部にある「Push」ボタン（↑の矢印アイコン）を押します。

   ![Forkのツールバー](../git_images/1-09_fork_toolbar.png)

   ※左から Quick Launch / Fetch / **Pull** / **Push** / Stash。今回使うのは3番目と4番目です。

5. 確認ダイアログが出るので、そのまま「Push」を押せばOK。
   数秒待ってエラーが出なければ送信完了です。

   ![Pushダイアログ](../git_images/1-09_fork_push_dialog.png)

   ※「Create tracking reference」にチェックが入っていればそのままでOK。「このブランチをGitHub側と紐づける」という意味です。
   ※初回はGitHubのログインを求められることがあります。1-04で連携していれば自動で通ります。

6. GitHubのリポジトリページをブラウザで開いて、リロードしてみてください。
   さっきのコミットメッセージが表示されているはずです。これでチーム全員があなたの作業を見られる状態になりました。

7. 次はプル。メンバーが送った変更を受け取る操作です。
   同じツールバーの「Pull」ボタン（↓の矢印アイコン）を押すだけ。こちらも確認ダイアログはそのままOKで大丈夫です。

8. 【超重要】作業を始める前は、必ずプルする

   これはチーム制作で一番大事な習慣です。理由はこうです。

   ```
   ✕ プルしないで作業した場合
      Aさん：古い状態のまま作業 → プッシュしようとする
      GitHub：「その間に他の人が更新しているよ」→ 拒否される
      Aさん：手作業でまとめ直すことになる

   ⭕ 作業前にプルした場合
      Aさん：最新を取得 → 作業 → プッシュ（そのまま通る）
   ```

   Unityを開く前に、まずForkでPull。これを毎回の習慣にしてください。

9. 【Unity特有の注意】プルする前に、Unityは閉じておく

   Unityを開いたままプルすると、Unityが開いているファイルが裏で書き換わってしまい、表示がおかしくなったりプロジェクトが壊れたりすることがあります。
   安全な手順はこれです。

   1. Unityで作業 → 保存 → **Unityを閉じる**
   2. Forkでプル
   3. Unityを開き直す

   ※慣れれば開いたままで大丈夫な場面も分かってきますが、最初は必ず閉じましょう。

10. 【エラーが出たら】「Push rejected」と表示された場合

    「あなたが作業している間に、他の人が先に送ったよ」という意味です。慌てなくて大丈夫。

    1. まず **Pull** する（相手の変更を受け取る）
    2. 自動でまとめられれば、そのまま **Push** し直す
    3. 自動でまとめられなかった場合（コンフリクト）は、1-13で対処法を扱います

11. プッシュしてGitHub上で確認できて、プルもできたら、今回は完成です！
    これでGitの基本操作（コミット・プッシュ・プル）がそろいました。次回からは、チームで作業がぶつからないための仕組みに入ります。
